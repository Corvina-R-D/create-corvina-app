# corvina-app-lib

Helm library chart with the templates shared by the charts of the apps generated by `create-corvina-app`.
The app chart declares it as a dependency and every file in its `templates/` folder is a one-line include, so a
template fix reaches the apps with a dependency bump instead of a resync:

```yaml
# Chart.yaml
dependencies:
  - name: corvina-app-lib
    version: "~0.1.0"
    repository: oci://europe-docker.pkg.dev/corvina-exorint/charts-public
```

```yaml
# templates/service.yaml
{{ include "corvina-app-lib.service" . }}
```

An app that needs something the knobs below don't cover replaces the include with its own template in that file
(the helpers, e.g. `corvina-app-lib.labels` and `corvina-app-lib.serviceAccount`, remain available), or adds new
files next to the includes.

## Templates

| Template | Resources |
|---|---|
| `app` | frontend Deployment, Service, ServiceAccount |
| `service` | backend Deployment, ConfigMap, Service, ServiceAccount, RoleBinding to wait for the migrator |
| `migrator` | migration Job, ServiceAccount, Role, RoleBinding |
| `gateway` | Istio Gateway, Telemetry, TLS fingerprints EnvoyFilter (`tlsClientLogging`) |
| `virtualService` | Istio VirtualService |
| `certificate` | cert-manager Issuer and Certificate |
| `secrets` | ExternalSecrets password generator, postgresql and redis passwords |
| `rabbitmq` | RabbitmqCluster, PodDisruptionBudget, fake default user, queues, exchanges and bindings |
| `registration` | post-install Job registering the app in Corvina |
| `backup` | Velero Schedule |
| `watchJobRole` | Role to watch Jobs |
| `prometheusRule.{healthAlerts,istio,resourceQuotas,infraAlerts,rabbitmq,redis}` | PrometheusRules |
| `serviceMonitor.{istio,rabbitmq}` | ServiceMonitors |

Pods don't mount the ServiceAccount token: only the `k8s-wait-for` init containers, which call the Kubernetes API,
mount it through the `corvina-app-lib.kubeApiAccessVolume` volume.

redis and rabbitmq resources render only when the `redis` and `rabbitmq` values exist (`base.yaml.gotmpl` has them
when the app was generated with them); `enabled: false` turns them off.

## App-specific knobs

They usually go in the app chart `values.yaml`, where templates are allowed in the values marked _tpl_ (in
`base.yaml.gotmpl` helmfile would render them first). [values.yaml](values.yaml) has a commented example of each.

| Value | Default | |
|---|---|---|
| `appName` | chart name without `corvina-app-` | gateway, certificate and issuer names |
| `service.serviceName` | `service-service` | backend Service, also the VirtualService destination |
| `service.healthPath` | `/v1/health` | backend readiness and liveness probes |
| `service.probeInitialDelaySeconds` | | |
| `service.pgEnv` | `true` | `false` drops the `PG_*` variables from the ConfigMap |
| `service.postgresHost` _tpl_ | `{{ .Release.Name }}-postgresql` | `PG_HOST` and the service the migrator waits for |
| `service.postgresPasswordEnv` | `PG_PASS` | env var with the postgresql password |
| `service.config` _tpl_ | | extra ConfigMap variables, overriding the defaults |
| `service.automountServiceAccountToken` | `false` | `true` mounts the ServiceAccount token in the backend container, for backends calling the Kubernetes API |
| `service.extraEnv` _tpl_ | | extra env vars of the backend and migrator containers |
| `virtualService.servicePrefixes` | `[/v1, /swagger-ui]` | URI prefixes routed to the backend |
| `virtualService.extraRoutes` _tpl_ | | Istio HTTP routes before the default ones |
| `rabbitmq.topology.queues` _tpl_ | | `[{name, durable, autoDelete, type, arguments}]` |
| `rabbitmq.topology.exchanges` _tpl_ | | `[{name, type, durable, autoDelete, arguments}]` |
| `rabbitmq.topology.bindings` _tpl_ | | `[{name, source, destination, destinationType: queue, routingKey, arguments}]` |

The other values (`gateway`, `cors`, `postgresql`, `redis`, `rabbitmq`, `service.envVar`, `backup`,
`registration`, `workloadIdentity`...) are the ones `base.yaml.gotmpl` already sets.

## Release

Bump `version` and `appVersion` in `Chart.yaml`, then push the `corvina-app-lib-X.Y.Z` tag: the
`publish-corvina-app-lib-chart.yaml` workflow pushes the chart to `oci://europe-docker.pkg.dev/corvina-exorint/charts-public`.

To try a change on an app before releasing, copy this folder to the app chart as `charts/corvina-app-lib` and render
with `helmfile template --skip-deps`.
